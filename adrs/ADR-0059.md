# ADR-0059 — Exigir aprovação manual antes de executar pull requests

Status: Aceito

## Contexto

Uma CI auto-hospedada pode executar código enviado em pull requests internos ou de forks. Em 2026-10-04, o usuário
aprovou a exigência de aprovação manual do mantenedor antes da execução para todos esses pull requests. A aprovação
deve valer somente para o SHA revisado; novos commits precisam aguardar outra aprovação. O pull request continua sendo
integrado por merge manual conforme [ADR-0046](ADR-0046.md). A implementação e os eventos concretos da versão
escolhida ainda precisam ser verificados; esta decisão não afirma que a proteção já esteja configurada.

## Decisão

Exigir aprovação manual do mantenedor antes de executar qualquer pull request, seja de branch interna ou de fork.
Cada novo SHA do pull request exige nova aprovação. Eventos de push não podem permitir que código de um pull request
contorne essa aprovação. Aprovar a execução não integra a alteração: o merge permanece uma ação manual separada.

## Consequências

- Positivas: código proposto não é executado na infraestrutura auto-hospedada antes da liberação consciente do
  mantenedor, e a aprovação fica vinculada ao conteúdo efetivamente revisado.
- Negativas ou limitações: contribuições aguardam uma ação humana; os eventos, permissões e comportamento para novos
  commits precisam ser testados na versão/configuração do Woodpecker escolhida.

## Alternativas Consideradas

Execução automática de pull requests sem aprovação manual prévia: incompatível com o requisito explícito aprovado
para a Fase 3. A seleção técnica entre eventos, `all_events` e allowlist ainda não foi validada e não constitui uma
decisão deste registro.
