# ADR-0076 — Usar o adapter oficial Keycloak com Authorization Code e PKCE na UI local

Status: Aceito

## Contexto

A UI local precisa iniciar uma sessão de navegador compartilhada com os serviços autenticados pelo Keycloak. O login
existente por senha usa o endpoint legado da API e mantém sessão no `sessionStorage`; ele não reutiliza a sessão do
navegador Keycloak. O usuário aprovou o uso do fluxo de navegador na especificação local de 2026-10-10.

## Decisão

Usar `keycloak-js` na versão exata 26.2.4 como adapter oficial do cliente público `python-demo-ui`. Inicializar com
Authorization Code, PKCE S256, `check-sso` e verificação de sessão em iframe desativada para o fluxo local de origem
única. Redirecionar somente para `https://app.localhost/admin`. Manter access e refresh tokens em memória, obter perfil
e papéis do endpoint validado `/api/admin/profile` e exigir o papel `admin` para concluir a sessão administrativa. O
cliente UI não contém segredo. O endpoint legado de senha e o comportamento padrão das composições existentes continuam
disponíveis; somente o Compose local raiz ativa SSO no build.

## Consequências

- O navegador pode reutilizar a sessão Keycloak já autenticada e a API continua validando issuer, audience e papéis.
- Recarregar a página reinicializa o adapter; tokens não são gravados no armazenamento legado da UI.
- O login local depende do adapter, de redirects exatos no realm e da disponibilidade do endpoint de perfil.
- Logout da UI encerra a sessão do adapter e redireciona para `/admin`; sessões de outros serviços não são encerradas
  automaticamente.
- A escolha é exclusiva do Compose local e não altera autenticação ou segredos de produção.

## Alternativas Consideradas

- Manter somente o password grant da API: descartado porque não compartilha a sessão do navegador Keycloak.
- Implementar Authorization Code, state, nonce e PKCE manualmente: descartado em favor do adapter oficial, que mantém
  esses detalhes do protocolo no cliente mantido pelo Keycloak.
