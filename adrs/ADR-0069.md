# ADR-0069 — Isolar o banco do Keycloak no MySQL da aplicação

Status: Aceito

## Contexto

A preparação Docker precisa persistir os dados do Keycloak e manter o MySQL já usado pela API. A spec aprovada em
2026-10-09 propõe um schema e um usuário próprios para o Keycloak dentro da mesma instância MySQL da aplicação.
O guia oficial do Keycloak lista MySQL 8.4 como versão testada e suportada.

## Decisão

Executar MySQL 8.4 para a aplicação e provisionar nele o schema `keycloak` e o usuário `keycloak`, com privilégios
limitados a `keycloak.*`. A API mantém seu schema e usuário separados. O provisionamento é idempotente, usa identificadores
fixos e parâmetros para senhas, e não altera o schema ou o usuário da API.

## Consequências

- Positivas: reduz uma instância de banco e mantém as credenciais e os privilégios dos serviços separados.
- Negativas ou limitações: API e Keycloak compartilham disponibilidade, recursos e ciclo de manutenção do servidor MySQL.
  Os arquivos de senha precisam permanecer estáveis para volumes existentes e ainda não há cofre ou rotação automática.
- A prova local e a escolha de versão não comprovam capacidade, operação ou migração de dados reais.

## Alternativas Consideradas

O registro da decisão aprovada não documenta avaliação de uma instância MySQL exclusiva para o Keycloak nem os motivos
para descartá-la.
